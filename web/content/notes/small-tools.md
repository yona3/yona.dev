毎日触る道具は、少しずつ手に馴染んでいく。dotfiles、シェルスクリプト、mise の小さなタスク、agent に持たせたスキル。最初から大きく設計したものより、使いながら削り、足し、また削った道具のほうが、不思議と長く残る。

完成品というより、生活道具に近い感覚で扱っている。全部書き直したくなる衝動は何度も来るけれど、毎日使う道具の角を一つずつ丸めていくほうが、自分には合っているらしい。

```txt
small tools, kept close
```

## 育て方

新しい道具を作るときは、最小限の動くものを先に置く。一行のシェル alias でも、3 行のスクリプトでもいい。整える前に、しばらく使ってみる時間を取る。

- 一週間使って気にならない不便は、たぶん本物の不便ではない
- 同じ手順を二度書いたら、関数か task に切り出す
- 名前が思い出せない道具は、たいてい使われていない
- 出力は短いほど読み返される

道具の最初の形は雑でいい。雑なまま使い続けて、痛いところが出てきてから直す。先に整えると、整えること自体が目的になりやすい。

## 捨てるタイミング

道具は増えるより減らすほうが難しい。半年触っていない alias、説明できなくなったスクリプト、何のためか思い出せない設定。そういうものに気づくたびに、まとめて消すようにしている。

### コマンド一つの試金石

「この道具、何のためにあるんだっけ」と一度でも思ったら、それは捨てる候補になる。代わりに置きたいものがあるかは、捨ててから考える。

```sh
# 消す前に、最後に使った日を確認するだけのワンライナー
git log -1 --format="%cs" -- path/to/script.sh
```

履歴を見て一年触っていなければ、消しても困らないことが多い。

## 名前を覚えておく

道具は名前で呼べると親しみが湧く。`mise run verify` のような決まった呼び名があると、毎回頭の中で組み立てなくて済む。

机の上に置く道具を増やしすぎないこと、増えたら一度しまうこと。それだけで、開発環境はずいぶん静かになる。
